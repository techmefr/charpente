The motion describes the movement, the timing describes the moment. Both are set independently of the theme.

## The motions

Each one is a CSS animation applied to every leaf of the area. Without an attribute, the motion from `motion` in the configuration applies.

<MotionDemos kind="motions" />

## The glitch split

`glitch` stays calm, then splits in short bursts: a cyan ghost and a magenta ghost separate to either side of the skeleton, like an RGB split, while the shapes jolt by a few pixels, then everything snaps back clean. The ghost colors are the `accent` and `accent2` tokens of the theme, with a cyan and magenta fallback.

The split is a `drop-shadow` filter applied to the loading container (`data-charpente-loading`) and not to each leaf, so it also works with captured zones, whose masks would otherwise clip it. A custom motion can do the same with a `container` field, keyframes applied to the container next to the leaf keyframes. It is disabled under `prefers-reduced-motion`.

## Ambient motions

`waves`, `matrix`, `snow`, `petals`, `leaves` and `sparkle` animate the layers of a theme instead of adding a glint: they move the `--charpente-flow` variable from 0 to 1, and a theme positions its layers with `calc(var(--charpente-flow) * <tile size>)`, so each layer scrolls by one whole tile per cycle and loops without a seam. Layers whose tiles have unrelated sizes never line up, which hides the repetition.

A theme picks its motion with `motion: 'waves'` (a name or a list). It applies when the configuration sets no `motion` of its own and an area has no `data-charpente-motion`. `waves`, `developer` and `crt` use it, and so do the `christmas`, `winter`, `spring`, `summer` and `autumn` recipes. Ambient motions cannot be combined with the others through the attribute.

## The CRT screen

`crt` turns the skeleton into a cathode-ray tube: thin scanlines scroll slowly over the area, a faint bar rolls from top to bottom, a green-tinted glow follows the shapes, the screen flickers for a fraction of a second now and then, and a dark vignette closes the edges. The glow takes the `accent` token, so it follows the theme.

The scanlines, the optional RGB mask and the vignette are drawn on an overlay of the loading container (its `::after`), declared with the `overlay` field of a motion, so it works in automatic and captured mode alike. Two variables tune it: `--charpente-crt-mask` (opacity of the red, green and blue stripes, `0.05` by default, `0` to remove them) and `--charpente-crt-vignette` (`0.38`). Under `prefers-reduced-motion` the flicker, the glow animation and the scrolling stop, and the scanlines stay in place. The `crt` theme, with its amber variant `crt-amber`, declares this motion as its default through the `motion` field.

```ts
defineCharpente({ defaultTheme: "crt", motion: "crt" })
```

## Speed

Durations are tuned to be neither nervous nor sluggish: `shimmer` 1.8s, `sweep` 2.4s, `pulse` 1.6s, `glitch` 3.4s (one burst per cycle), `crt` 5s (7s for the scanline scroll), all with `ease-in-out` except the stepped `glitch` and the linear `crt`. Every duration is multiplied by `--charpente-speed` (default `1`): `style="--charpente-speed: 0.5"` makes the motions twice as fast, `2` twice as slow. It can be set on `:root` or on one area.

## One sweep across the page

`sweep` draws a single band that crosses the whole viewport instead of one band per element, like the loading screens of big feeds. It is pure CSS: the shine layer is attached to the viewport. Browsers that ignore fixed backgrounds, such as Safari on iOS, show one band per element instead.

```ts
defineCharpente({ motion: "sweep" })
```

## Combining and conflicts

`data-charpente-motion` accepts several names separated by a space, **sorted alphabetically**. The compiler generates one rule per combination, up to six declared motions; beyond that, only single motions are generated.

```html
<div data-charpente-loading data-charpente-motion="pulse shimmer" aria-busy="true" inert>
  ...
</div>
```

The wrappers sort the names for you: `<Charpente :motion="['shimmer', 'pulse']">` produces the attribute above.

Two motions that animate the same property conflict: the last one in the list wins. In the configuration, the compiler reports it with a warning; on an attribute, nothing is reported.

```ts title="charpente.config.ts"
export default defineCharpente({
  motion: ['pulse', 'shimmer'],
  timing: { delay: 120, stagger: 40 },
})
```

## The delay

`delay` postpones the appearance of the skeleton. In the meantime, the elements are hidden: a load shorter than the delay causes no flicker. Global setting in `timing.delay`, local setting with `--charpente-delay`.

<MotionDemos kind="delays" />

## The offset between elements

`stagger` adds a delay proportional to the position of each element among its siblings (from 1 to 16): the skeleton appears in a cascade, and every motion starts from one element to the next. Global setting in `timing.stagger`, local with `--charpente-stagger`.

```html
<div
  data-charpente-loading
  data-charpente-motion="pulse"
  style="--charpente-delay: 600ms; --charpente-stagger: 150ms"
  aria-busy="true"
  inert
>
  ...
</div>
```
