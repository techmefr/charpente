Three steps: install the package, declare a theme, then mark the area that is loading.

## 1. Install

```bash
pnpm add charpente
# or: npm install charpente / yarn add charpente
```

## 2. Declare the configuration

A `charpente.config.ts` file at the project root. Everything is optional: without configuration, you get the `solid` theme and the `shimmer` motion.

```ts title="charpente.config.ts"
import { defineCharpente } from 'charpente'

export default defineCharpente({
  defaultTheme: 'solid',
  motion: 'shimmer',
  timing: { delay: 120 },
})
```

## 3. Mark the area that is loading

Three attributes are enough, set together on the container:

- `data-charpente-loading` enables the skeleton on the whole subtree.
- `aria-busy="true"` tells screen readers that the area is being updated.
- `inert` takes the area out of keyboard navigation and the accessibility tree, so nobody can click a fake button.

```html
<section data-charpente-loading aria-busy="true" inert>
  <h2>Team</h2>
  <p>Four members</p>
  <img src="/photo.jpg" alt="Team photo" width="320" height="120" />
  <button type="button">Invite</button>
</section>
```

When the data arrives, remove the three attributes: the real content is already there, in the same place, with no layout shift.

| Name | Where | Role |
| --- | --- | --- |
| `data-charpente-loading` | container | Enables the skeleton. |
| `data-charpente-theme` | container | Picks a theme, otherwise `defaultTheme`. |
| `data-charpente-motion` | container | Names sorted alphabetically, separated by a space, or `none`. |
| `data-charpente-block` | an element | Paints the element as a single block and hides its children. |
| `data-charpente-ready` | container | Set for a few moments after loading for a fade-in. |
| `--charpente-delay` | style | Delay before the skeleton appears, in `ms`. |
| `--charpente-stagger` | style | Offset between siblings, in `ms`. |

## Vite plugin and CLI

The Vite plugin compiles the configuration on the fly and exposes two virtual modules. It re-reads the file on every change.

```ts title="vite.config.ts"
import { charpente } from 'charpente/vite'

export default { plugins: [charpente()] }
```

```ts title="main.ts"
import 'virtual:charpente.css'
```

`virtual:charpente.theme` gives today's theme according to the [seasonal calendar](/charpente/calendar/):

```ts
import { activeTheme } from 'virtual:charpente.theme'

document.documentElement.dataset.charpenteTheme = activeTheme()
```

Without Vite, the `charpente build` command writes the CSS to a file. The `charpente theme` command prints the active theme for a date.

```bash
charpente build --config charpente.config.ts --out charpente.css
charpente theme --date 2026-10-31
```

The `charpente-vue` package provides a `<Charpente>` component that sets the attributes, announces the loading state and handles the fade-out.

```vue
<script setup lang="ts">
import { Charpente } from 'charpente-vue'
</script>

<template>
  <Charpente :loading="pending" label="Loading the profile" :motion="['pulse', 'shimmer']" :delay="200">
    <UserCard :user="user ?? placeholder" />
  </Charpente>
</template>
```

| Prop | Type | Default | Role |
| --- | --- | --- | --- |
| `loading` | boolean | `false` | Enables the skeleton, sets `aria-busy` and `inert`. |
| `tag` | string | `div` | Root element rendered. |
| `theme` | string | none | Local theme. |
| `motion` | string or string[] | none | Local motions, sorted automatically. |
| `delay` | number | none | Delay in ms. |
| `stagger` | number | none | Offset in ms. |
| `label` | string | empty | Text of a `role="status"` region read during loading. |
| `revealMs` | number | `260` | Duration of `data-charpente-ready` after loading. |
